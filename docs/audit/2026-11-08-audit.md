# 2026-11-08 — cyrius-mine-cart 0.3.2 code audit

**Scope:** all of `src/`, `tools/`, `tests/` and `.github/workflows/` at 0.3.1 (8,926 lines of Cyrius), and
the AGNOS kernel interface the game consumes, compared against agnos 1.57.17. The Cyrius toolchain and
the kernel itself are out of scope; how this repo uses them is in scope.

**Result:** 29 distinct findings: **0 critical, 1 high, 11 medium, 17 low.** All are repaired, one of them
(A1) only as far as a program can: the root cause is in the kernel.

The simulation and the records it emits came through clean. The op `0x0F` mirror in `check.cyr` matches
the kernel, and the kernel's real validator refused none of 140,000 frames at seven console sizes. What
the audit found instead was **false results**: a replay that could not pass for a ride on real hardware,
exit codes that claimed success after a failure, and tests that could not fail.

## Method

1. **Baseline.** `--check`, `--sim`, `--replay`, a film and the `--wav` mix at 0.3.1, before any change.
2. **Tools.** `cyrius lint --strict`, `lint --strict-deferrals`, `deny`, `vet`, `capacity --check`, and
   execution coverage. Then builds with `--bounds`, `-D CYRIUS_POISON` and both, run through the gate,
   three-hour rides, 668 fuzzed replay logs and an argument matrix.
3. **Find.** Four independent auditors, one per surface: the kernel boundary (A), the simulation and
   replay parser (B), the renderer and audio (C), entry points and the gates themselves (D). A finding
   had to be CONFIRMED by a probe that ran, or TRACED through the exact code path.
4. **Verify.** Every finding was checked against the code and, where it cites the kernel, against the
   kernel's source before any repair. Surfaces B and D, and a separate reading of `rp_frame_hash`, reached
   the two worst replay defects independently.
5. **Repair and prove.** Each repair's test had to fail with the defect put back: see Regression proof.

was exercised against a mock kernel, or traced where the report says so.

### Also corrected, found during the audit

- `gate.cyr` said `|D|` grows with the draw offset. It does not; vertices and sample points shift together.
- The gate's `|N|` bound was the validator's 2^62. The shader's divide runs 56 iterations, so 2^56 is real.
- `ci.yml`'s comment, and the 0.3.0 changelog, said an undefined function always builds with exit 0. A
  reachable one is a hard error; only one in dead code is a warning.

## Regression proof

alone, and the gate had to exit 90: **26 reintroduced, 26 caught.**

B1, B2, D6, three replay-test holes from B5 (frame compare, death restart, and six fields missed by the
reset), B3, B4 (twice: linear and cubic), B6, D5 (twice), C1, C2, C3, C4 (each clamp), C6, D7, D9, D10.

## Noted, not changed

- **For agnos:** the back buffer's stride should come from `fb_pitch()` rather than `boot_info` (A1), and
  `gpo_validate_triperspec` permits |N| up to 2^62 while `tri_persp.s` divides 56 bits.
- `#85`'s return value is ignored in the ride; if a fill timed out, the only effect is a stale surround.
- `--replay /dev/zero` reads 2 GiB and refuses after 6 s.
- `cart_derail_frac` and `fxt_near` have no callers.
- Five comments say "not yet" or "for now" without a cross-reference (`lint --strict-deferrals`).
- `rp_state` hashes state, not words, so input bits the simulation ignores can change without a replay
  noticing. That is by design: those bits did not change the ride.

## What this audit could not establish

Nothing here has run on a GPU, and nothing since 0.2.1 has. The AGNOS-only repairs ran against a mock
kernel. `--verify` on the hardware is still the only instrument that can see a picture that is ABI-legal
and wrong.
